# Rebuild sequence

This is a dependency-oriented reconstruction order, not a click-to-deploy procedure.

For the start-here overview that names the building blocks, their connections, site prerequisites, and coverage, read [`../blueprint.md`](../blueprint.md) first.

## 1. Establish durable source and authority

Define the source hierarchy, database backup contract, operator authority, OPA/verbatim rules, and review evidence before rebuilding any dependent surface.

## 2. Rebuild the durable data planes

Stand up the coordinator database substrate and Cairn lifecycle records first. Preserve RFC, KB, research, seed, scratch, task, Swatter, Failure Episode, authorization, review, memory, and handoff state before adding derived views.

## 3. Rebuild Zerobrain integration glue

Connect the durable data planes through the Zerobrain subsystem: API contracts, authorization, event delivery, dashboard projections, review paths, and evidence flows. Keep derived indexes and presentation layers failure-isolated.

## 4. Rebuild coordinator execution

Add node identity, bootstrap, session tokens, messaging, task routing, lifecycle, manual-mode state, and explicit-wake processing. The coordinator must be live-state truth without becoming the owner of every domain record.

## 5. Rebuild node continuity

Add memory blocks, handoff, durable workplans, identity growth boundaries, Molt safety, and successor verification. Do not claim context freshness without observed evidence.

## 6. Rebuild operator and work surfaces

Add Superdash, review, Swatter, TotemTask, Gary, and operational evidence views over the durable records. Treat plans, dashboards, indexes, and proof files as derived or coordinating surfaces.

## 7. Add liveness as a mode-dependent capability

Keep manual mode as the default. Rebuild the Breathbus and automated `bb4-poll` contract only as an explicit opt-in with credit, authority, rollback, and triple-gate review.

## 8. Migrate valuable historical design

Triage RFCs, seeds, KBs, research, and legacy breathing variants into keep, salvage, archive, or ditch dispositions. Do not make historical artifacts current merely by copying them.

## Rebuild exit criteria

- every durable state has one identified owner;
- every derived surface has a rebuild path;
- every authority path is auditable;
- every lifecycle transition has evidence and rollback;
- unresolved boundaries are recorded rather than guessed;
- a fresh operator can navigate from COHORT to the source record for each major contract.
