# System guides

Each system guide should answer five questions:

1. What problem does the system solve?
2. What state does it own, and what state does it merely display or relay?
3. Which systems call it, and which systems does it call?
4. What are the safety, authorization, and evidence gates?
5. How does it behave in manual mode, automated mode, failure, recovery, and Molt?

## Initial guide set

The first documentation wave should cover:

- MCP coordinator and cohort messaging
- Zerobrain backend and dashboard boundary
- fleet boot, bootstrap, and node identity
- manual mode and TotemTask
- authorization, OPA, and verbal-versus-key authority
- task board, Swatter, and closure evidence
- Spyglass RFC planning and research
- review and reviewer gates
- identity, memory, and session handoff
- lifecycle, Molt, and recovery
- Gary
- breathing systems: HB3 lineage, Breathbus, and advanced variants

Merit, Lessons, and retired or historical variants are intentionally deferred until their current contracts are needed.
